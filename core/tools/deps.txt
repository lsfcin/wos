# Every external dependency the core/tools surface needs, declared: what installs it, what checks it, and what its absence breaks. Read by core/tools/wos/deps
# (the check runner) and by core/tools/test/wos/test_deps.py (the class check).
#
# WHY THIS FILE EXISTS: four features were installed straight into .venv to unblock a tool and
# never written down, so a fresh clone lost them SILENTLY — the tool did not crash, it returned a
# worse answer or a misleading error. The `breaks` column is the cure: it says what the failure
# LOOKS like, because the expensive case (secretstorage) reads like bad credentials.
#
# Tab-separated. Columns:
#   name     the installable name, exactly as the install command spells it
#   kind     pip | system | apt | npm | npx | binary | service — how it arrives, which fixes how it is
#            installed. `system` asks platform_law.package_install which manager this machine has;
#            `apt` names one. A row earns `system` only when its name is VERIFIED to resolve on the
#            others — ffmpeg does (winget Gyan.FFmpeg, checked 2026-08-30), tesseract-ocr,
#            poppler-utils and ddgr do not, so they stay `apt` rather than claim a portability
#            nobody checked. `service` is the one kind NOTHING INSTALLS: a remote API this surface
#            depends on, which is present or absent by someone else's decision. It was added
#            2026-09-13 because every other row here asks whether a module IMPORTS, and a whole
#            research run found core/tools/paper/papers dead on both arms while `deps` reported
#            all declared dependencies present — the first measured instance of ROADMAP.md
#            § Portability's *no check falsely greens*. A check that cannot fail is not a check.
#   import   the python module it provides, or - for anything not imported by our code.
#            THIS IS THE JOIN KEY: test_deps.py fails on any third-party import missing from here.
#   check    HOW to ask whether the dep is here, as `<verb>:<arg>`. Three verbs, dispatched in
#            core/tools/wos/deps:
#              import:<module>      import it with this clone's interpreter (platform_law)
#              venv-script:<name>   a console script installed INTO the venv (platform_law)
#              cmd:<command>        a binary on PATH; run from the workspace root
#            IT USED TO BE A RAW SHELL COMMAND, and 17 of 27 rows spelled the POSIX venv bin directory -- a
#            directory that is `.venv/Scripts` on Windows. So on any clone but the authoring one
#            every one of those checks failed to RUN and the tool reported the dependency MISSING:
#            the same false answer the old `make verify-fast` gate gave. The registry's own rule is
#            that a dependency has one name; a per-machine spelling per row broke it.
#   feature  the feature name that owns it — same names SETUP.md declares per step
#   floor    the OLDEST version that still works, or `-` when nobody has established one. A FLOOR
#            AND NOT A CEILING, which is what ROADMAP.md asked for: the portability failure here is
#            an apt or a distro shipping something too old, never a release from the future. A
#            clone with an older build does not crash — it loses a capability quietly, which is the
#            same silence the `breaks` column exists to end.
#            `-` IS THE HONEST DEFAULT AND MOST ROWS KEEP IT. A number here is a CLAIM that the
#            version below it was seen to fail, so stamping whatever this machine happens to run
#            would manufacture 31 facts out of one laptop — the same error that split profile.txt
#            into a versioned base and a per-machine local. Fill a row when a real break is found,
#            and write where it was found; never on installation.
#   breaks   what stops working without it, written in the words the FAILURE uses
#
