# Every toggleable feature this workspace has, declared: what group it belongs to, how hard it
# enforces, whether it is general or Lucas-specific, and whether it can actually be switched off.
# Read by core/hooks/feature_law.py; the answers live in core/profile.txt.
#
# WHY THIS FILE EXISTS: the ablation bench ran once and produced no signal for exactly one reason —
# there was no clean way to turn a single feature off. No feature in this workspace has ever been
# measured. This file is the instrument, not a config system: it NAMES which hook/skill/tool is
# wired and never restates the rule that hook enforces. A checker that restates the law is the
# drift the checkers exist to catch.
#
# THE TWO VOCABULARIES IT RECONCILES, and it does not invent a third:
#   SETUP.md          declares a name per install step ("what do I run")     -> the `install` column
#   core/tools/deps.txt declares a name per dependency ("what breaks")       -> the `name` column
# Thirteen each, four shared verbatim. Both are the wrong shape for a toggle on their own: neither
# covers the enforcement layer, which has no install step and no dependency and is three quarters
# of what Lucas asked to be able to switch off. So this key set is a strict superset of their union.
#
# Tab-separated. Columns:
#   name         the feature's identity. Every `feature` in core/tools/deps.txt appears here.
#                A NAME AND THE FILE IT GOVERNS CARRY THE SAME NAME (Lucas, 2026-08-17), enforced
#                for the skills group by test_features.py: `roundup` is core/skills/roundup.md.
#                Descriptive suffixes read well in a registry and cost a lookup at every other
#                site, which is how `craft-flow` came to name a file called loops.md whose flow
#                was called craft — one feature, three spellings, none of them wrong alone.
#   group        hooks | tools | skills | agents | flows | norms — the tree's own layers, so a
#                feature is findable by opening a directory. A feature may be a COMBINATION,
#                written with `+`: `latex` is a pre-commit gate plus the tool family that gate
#                calls. The five groups this replaced (2026-08-17) named `capabilities`,
#                `context-tree` and `brain`, none of which is a directory — every wired row in
#                the latter two pointed into core/hooks/, so the claim written HERE that the
#                groups matched the tree died to one `ls core/`. `norms` is the only layer with
#                no code: rules obeyed rather than enforced, the INDUCED half of the line whose
#                ENFORCED half is file_law.py / schema_law.py / feature_law.py.
#   runs         automatic | on-demand — WHO STARTS IT. An automatic feature fires unbidden and so
#                has a moment; an on-demand one waits to be called and has none. Added 2026-08-18
#                because this file carried one column where it had two facts: `enforcement: none`
#                meant BOTH "fires by itself and applies no pressure" and "you call it", and that
#                ambiguity made a reader of this very registry report the capability half of the
#                workspace as dead weight. DO NOT DERIVE IT FROM `enforcement` — eleven rows cross,
#                and they are the reason the column exists: six are automatic and enforce nothing
#                (rtk-compaction, subtree-read-tracking, precompact-wipe, brain-attention,
#                opencode-plugin, and caveman, which activates itself from a SessionStart hook);
#                four are on-demand and still push (crowding-limit, context-head-budget,
#                declared-deps, diagram). The subcategory of an on-demand
#                feature is its `group` and no third column is needed: a skill is typed as /name,
#                a tool is called by path. Named `automatic`/`on-demand` rather than
#                `passive`/`active` because this registry's other job is saying which features are
#                switched ON, and "an active feature" would be ambiguous at every other site.
#   install      the SETUP.md step that installs it, or - . Every `> feature:` name in SETUP.md
#                appears in this column. THIS IS THE JOIN: three files, one vocabulary.
#   enforcement  blocks | warns | generates | advises | none — how hard it pushes, once something
#                has started it. Orthogonal to `runs` above, which says what starts it.
#   scope        general | lucas . IS THE CAPABILITY GENERIC? Not "is the content Lucas's" — read
#                the `buys` sentences and nearly all of them are written for anyone, because a
#                Google account, a Telegram bot and a set of goal files are CONFIG, not capability.
#                The column claimed until 2026-09-15 to be "what the public sync is allowed to
#                copy", and answering that question with this one would have stripped a student's
#                clone of caveman, the skill wrappers, the OAuth and the link shortener. Privacy is
#                a fact about CONTENT — brain/, branches/, academy/, models/, segredos.env, and the
#                floor of what git tracks at all — and that is where the sync reads it. Two rows
#                are `lucas`, both references bound to one of his projects.
#   wired        path of the file that calls feature_law.is_enabled(), or `n/a <reason>`, or - .
#                COMMA-SEPARATED when the feature spans layers, and the plural is load-bearing
#                rather than tidy: `latex` is a pre-commit gate AND the tool family that gate
#                calls, so a switch that stopped only the tool would leave the gate reading the
#                tool's refusal as a violation and BLOCK the commit it was meant to relax.
#                A `-` IS A FINDING, counted by `core/tools/wos/features --findings`: a feature
#                that cannot be switched off is entangled with the scaffold rather than sitting on
#                it, and the target for that count is ZERO.
#                `n/a` means NO IN-PROCESS SWITCH, never "exempt" — the feature is still ablatable,
#                by building a clone variant without it (core/SPECS.md § AD-14). A row is n/a only
#                because a switch CANNOT exist, never because wiring one is work: the two carrying
#                it are a GitHub credential and a NetworkManager profile, machine state a SETUP.md
#                step installs and no code here authors. Wiring one would mean claiming a switch
#                that cannot revoke what it names. They keep their row because the SETUP join
#                above requires one, so deleting the row would break the join, not pay the debt.
#                Do not hide the count by claiming a row is wired when it is not. The honesty test
#                in test_features.py is a BEHAVIOURAL CHECK: it runs the feature both ways and
#                fails unless the observable changes. A grep for the name would pass on a guard in
#                an unreachable branch, and would force one call site per row — which is why the
#                whole skills group shares one wiring point in the mirror.
#   ships        the rest of the tree the switch cannot run without — comma-separated, `*` allowed,
#                `-` meaning "exactly what `wired` already says". Added 2026-09-16, because `wired`
#                names the SWITCH and not the FEATURE: `caveman` is one config.js and thirty-six
#                other files, and the public sync read that as thirty-six files nothing could say a
#                purpose for. Write only what is NOT already derivable — a `.pyi`, a CONTEXT.md, an
#                imported sibling and a data file named by a literal are all followed automatically
#                (core/tools/wos/publish/crossing.py), and restating one here is the drift these
#                checks exist to catch. A file left in no row's `ships` is the audit list the
#                cutting campaign reads, so leaving it out is an ANSWER, not an omission.
#   buys         one sentence: what it is for and what it buys you. Required, because nobody
#                accepts an enforcement layer they cannot see the value of, and writing this
#                sentence per feature is itself an audit of whether the feature earns its place.
#
